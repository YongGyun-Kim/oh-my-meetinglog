# 서비스 문구 기준

적용일: 2026-10-20. UI, 버튼, 빈 화면, 처리 상태, 도움말, 사용자에게 표시하는 오류 메시지에 적용한다. 에이전트 답변과 개발 문서의 평서체는 [AGENTS.md](../AGENTS.md)를 따른다.

## 임시 참고 기준

토스가 공개한 UX 라이팅 원칙을 참고해 우리 서비스의 임시 문구 기준을 정한다. 사용자가 이해하는 말로 필요한 정보를 짧게 전달하고, 동작을 예상할 수 있게 쓰는 방향을 적용한다. 토스의 브랜드 문구를 복제하거나 공식 제휴처럼 표현하지 않는다. [토스의 8가지 라이팅 원칙들](https://toss.tech/article/21022)

사용자의 선택을 존중하고, 감성적 수사·과장·서비스 의인화는 사용하지 않는다. 이 조건은 이 프로젝트에서 정한 기준이다.

## 문체와 구성

- 설명과 상태 안내는 짧은 해요체로 쓴다. 예: `기록을 불러오고 있어요.`
- 제목은 화면의 기능이나 현재 상태를 말한다. 예: `대화 기록`, `저장된 기록이 없어요`.
- 버튼은 누르면 하는 일을 적는다. 예: `녹음 시작`, `파일 가져오기`, `다시 분석`.
- 짧은 상태 이름은 문장으로 늘이지 않는다. 예: `전사 중`, `분석 완료`, `처리 대기`.
- 한 문장에 한 가지 내용을 담는다. 같은 화면에서 제목과 설명을 의미 없이 반복하지 않는다.
- 일상적인 한국어를 사용한다. 장식용 영어, 은유, 유행어를 넣지 않는다.
- 기능 용어는 일관되게 쓴다. `전사`는 음성을 글로 바꾸는 작업, `분석`은 전사를 요약·분류하는 작업이다. 처음 접하는 화면에서는 필요한 경우 뜻을 풀어 쓴다.

## 상황별 작성 방식

| 상황           | 작성 방식                      | 예                                                            |
| -------------- | ------------------------------ | ------------------------------------------------------------- |
| 기록 없음      | 현재 상태와 시작할 행동        | 저장된 기록이 없어요. 녹음을 시작하거나 파일을 가져와 주세요. |
| 검색 결과 없음 | 검색 범위와 다음 행동          | 검색 결과가 없어요. 다른 제목으로 검색해 주세요.              |
| 처리 중        | 실제 실행 중인 작업            | 음성을 글로 바꾸고 화자를 구분하고 있어요.                    |
| 결과 없음      | 결과가 없다는 사실             | 아직 분석 결과가 없어요.                                      |
| 확인한 오류    | 확인한 문제와 가능한 다음 행동 | 서버에 연결하지 못했어요. 서버가 실행 중인지 확인해 주세요.   |
| 전사 수정 후   | 어떤 버전의 결과인지           | 수정 전 전사를 바탕으로 만든 분석이에요.                      |
| 삭제           | 삭제 대상과 영향               | 원본 음성, 전사와 분석을 삭제해요. 진행 중인 처리도 중지돼요. |

## 사실과 상태

- 실제 처리 중일 때만 처리 중이라고 쓴다. 대기·실패·미실행 상태를 진행 중으로 표현하지 않는다.
- 원인을 확인하지 못했다면 추측하지 않는다. 실패했다는 사실과 사용자가 할 수 있는 행동을 쓴다.
- 정확도·처리 시간·성공을 측정 없이 보장하지 않는다.
- 저장 위치와 처리 위치를 구분한다. 외부 API를 사용할 수 있는 화면에 모든 처리가 로컬이라는 문구를 고정 표시하지 않는다.
- 외부 전송, 비용, 삭제 같은 선택에 필요한 조건을 감추지 않는다.
- 사용자의 녹음 제목·전사 원문·인용문은 서비스 문체에 맞추려고 바꾸지 않는다. AI가 만든 분석 내용도 UI 문구와 구분한다.
- 서버 오류를 해요체로 바꾸기 위해 화면에서 문자열을 기계적으로 치환하지 않는다. 해당 오류를 정의하는 위치에서 의미를 유지하며 수정한다.

## 적용 방법

새 문구와 수정하는 문구에 이 기준을 적용한다. 이번에는 기록 목록·녹음·파일 입력·결과·설정 화면의 정적 안내와 프런트엔드 오류를 정리한다. 서버가 반환하는 기존 오류 문장은 해당 코드를 수정할 때 함께 정리한다.

문구를 바꾼 뒤에는 실제 기능·상태와 맞는지, 버튼·접근성 이름·테스트의 참조가 일치하는지 확인한다. 화면 문구만 바꿀 때는 번역 시스템이나 문구 전용 실행 설정을 새로 만들지 않는다.
