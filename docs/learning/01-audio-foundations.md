# 1. 소리에서 디지털 데이터까지

[읽기 안내](README.md) · 다음: [음성 인식의 원리](02-speech-recognition.md) · [용어집](07-glossary.md)

학습 목표는 음성 파일을 숫자 배열로 이해하고, 파일 크기와 음성 특징의 의미를 설명하는 것이다.

## 1.1 소리는 공기 압력의 변화다

사람이 말하면 성대와 입·혀의 움직임이 공기 압력을 변화시킨다. 마이크는 그 변화를 전기 신호로 바꾼다. 컴퓨터는 이 신호를 일정한 시간 간격으로 측정해 숫자로 저장한다.

예를 들어 `0.00, 0.12, 0.31, 0.08, -0.16`처럼 연속된 값이 있다. 이 값을 시간순으로 그린 것이 **파형**이다. 예시 값은 측정값을 정규화한 표현이며, 실제 파일의 저장 방식은 형식마다 다르다.

파형에는 시간에 따른 신호 진폭이 나타난다. 진폭과 사람이 느끼는 소리 크기는 관련이 있지만 완전히 같은 값은 아니다. 파형을 눈으로 보고 한국어 문장을 바로 읽을 수 있는 것도 아니다.

## 1.2 샘플레이트와 비트 깊이

**샘플레이트**는 1초에 몇 번 측정하는지다. **비트 깊이**는 각 측정값을 몇 비트로 표현하는지다. 비트는 0 또는 1 하나이며, 8비트가 1바이트다.

| 설정                 | 의미                                    |
| -------------------- | --------------------------------------- |
| 16,000Hz, 또는 16kHz | 채널마다 1초에 16,000번 측정            |
| 16bit PCM            | 측정값 하나를 16비트, 즉 2바이트로 저장 |
| 모노                 | 채널 1개                                |
| 스테레오             | 채널 2개                                |

여기서 16kHz는 사람 목소리의 음높이가 아니다. 측정 빈도다. 적절한 필터링을 전제로 16kHz 샘플링은 약 8kHz 미만의 주파수 성분을 표현한다. 더 높은 주파수가 필요하면 더 높은 샘플레이트를 사용한다.

수치를 낮추는 리샘플링에는 주파수 필터링이 필요하다. 배열에서 일정 간격으로 값을 지우는 것만으로 안전한 변환이 되는 것은 아니다. 반대로 16kHz를 48kHz로 늘려도 원래 없던 고주파 정보가 복원되지는 않는다.

비트 깊이를 낮추면 값을 더 거칠게 표현한다. 음량이 너무 커 저장 가능한 범위를 넘으면 **클리핑**이 발생한다. 이미 손상된 파형은 나중에 음량만 줄여도 원래 상태로 돌아오지 않는다.

이 개념들의 표준적인 정의는 [MDN 디지털 오디오 설명](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_concepts)에서도 확인할 수 있다.

## 1.3 1시간 음성의 크기 계산

압축하지 않은 PCM 본문 크기는 다음과 같다. 파일 헤더는 제외한 계산이다.

```text
바이트 수 = 초 × 초당 샘플 수 × 채널 수 × 샘플당 비트 수 ÷ 8

1시간, 16kHz, 모노, 16bit:
3600 × 16000 × 1 × 16 ÷ 8
= 115,200,000바이트
= 115.2MB, 약 109.9MiB
```

MB는 1,000,000바이트, MiB는 1,048,576바이트를 기준으로 한다. 둘을 섞으면 크기 비교가 달라진다.

같은 파형을 계산 중 `float32` 배열로 보관하면 샘플당 4바이트를 사용한다. 위 조건에서 파형 배열 하나만 230.4MB가 된다. 모델 가중치, 중간 계산값, 복사본은 여기에 추가된다. **파일 크기와 실행 메모리는 다르다.**

## 1.4 WAV·MP3·Opus는 무엇이 다른가

파일의 **컨테이너**와 소리를 저장하는 **코덱**을 구분한다.

| 예             | 이해할 점                                          |
| -------------- | -------------------------------------------------- |
| WAV 안의 PCM   | 이 프로젝트가 모델용으로 만드는 압축하지 않은 음성 |
| MP3            | 손실 압축된 음성·음악에 널리 사용하는 형식         |
| WebM 안의 Opus | 브라우저 녹음에서 사용할 수 있는 조합              |
| MP4 안의 AAC   | 브라우저 지원 상태에 따라 선택할 수 있는 조합      |

손실 압축은 저장량을 줄이면서 일부 정보를 버린다. 압축 파일을 WAV로 변환하면 모델이 처리할 숫자 배열을 얻을 수 있지만, 이미 사라진 정보가 복원되지는 않는다.

우리 브라우저는 지원 형식을 검사한 뒤 녹음 형식을 선택한다. 따라서 사용자가 받은 원본 파일을 항상 WAV 또는 무가공 마이크 데이터로 가정하면 안 된다. [현재 녹음 코드](../../web/src/features/recordings/useRecorder.ts)

## 1.5 주파수와 스펙트로그램

**주파수**는 반복되는 진동이 1초에 몇 번 일어나는지다. 실제 말소리는 여러 주파수 성분이 시간에 따라 변하는 신호다.

음성 처리에서는 다음 과정을 자주 사용한다.

1. 파형에서 수십 밀리초의 짧은 구간을 잡는다.
2. 구간 가장자리의 영향을 줄이도록 창 함수를 적용한다.
3. 푸리에 변환으로 주파수별 성분을 계산한다.
4. 창을 조금씩 이동하며 결과를 시간순으로 배열한다.

이것이 짧은 시간 푸리에 변환, **STFT**의 기본 생각이다. 결과를 시간·주파수·세기로 나타내면 스펙트로그램이 된다. 색이 있는 그림은 숫자 배열을 시각화한 것이다. 모델이 반드시 그림 파일을 읽는다는 뜻은 아니다.

**Mel 스펙트로그램**은 주파수를 사람의 청각 특성을 참고한 대역으로 묶는다. 로그 변환을 더하면 값의 넓은 범위를 다루기 쉬워진다. 음성 모델마다 특징의 대역 수와 계산 조건이 다르다.

Whisper의 원 논문은 16kHz 음성, 25ms 창, 10ms 이동 간격과 Mel 특징을 사용한다고 설명한다. 이 수치는 모든 음성 모델의 공통 규격이 아니다. [Whisper의 입력 표현](https://arxiv.org/html/2212.04356v1#S2.SS2)

```mermaid
flowchart LR
    A[파형: 시간별 진폭] --> B[짧은 창으로 나누기]
    B --> C[주파수 성분 계산]
    C --> D[Mel 대역·로그 변환]
    D --> E[모델에 넣는 숫자 배열]
```

## 1.6 간단한 실습: 소리를 숫자로 만들기

Python 표준 라이브러리만 사용하는 예제다. 음성을 녹음하거나 모델을 다운로드하지 않는다. 440Hz 순음을 1초 생성하고, 임시 WAV 파일의 정보를 확인한 뒤 삭제한다. 순음에는 발음 정보가 없으므로 한국어 문장 인식 실험이 아니다.

```python
import math
import struct
import tempfile
import wave
from pathlib import Path

sample_rate = 16000
samples = [
    round(0.2 * 32767 * math.sin(2 * math.pi * 440 * n / sample_rate))
    for n in range(sample_rate)
]
pcm = struct.pack(f"<{len(samples)}h", *samples)

with tempfile.TemporaryDirectory() as directory:
    path = Path(directory) / "tone.wav"
    with wave.open(str(path), "wb") as output:
        output.setnchannels(1)
        output.setsampwidth(2)
        output.setframerate(sample_rate)
        output.writeframes(pcm)
    with wave.open(str(path), "rb") as source:
        print(source.getframerate(), source.getnframes(), source.getnchannels())
    print(len(pcm))
```

예상 출력은 첫 줄 `16000 16000 1`, 둘째 줄 `32000`이다. `n`은 샘플의 순번이고, `n / sample_rate`는 해당 샘플의 시각이다.

## 1.7 확인 문제

1. 16kHz 모노 음성 10초에는 몇 개의 샘플이 있는가?
2. 같은 조건에서 16bit PCM과 float32 배열은 각각 몇 바이트인가?
3. 모노 파일을 두 채널로 복제하면 두 사람의 소리를 분리할 수 있는가?

<details>
<summary>해설</summary>

1. 160,000개다.
2. PCM 본문은 320,000바이트, float32 배열 하나는 640,000바이트다.
3. 복제한 두 채널에는 같은 정보가 있다. 별도의 마이크에서 얻은 공간 정보나 사람별 신호가 생기지 않는다.

</details>
