## 이 프로젝트가 다루는 문제

목표는 **Plaud 없이도 양질의 전사를 얻고, 그 전사로 후속 작업을 자동화하는 것**이다. Plaud의 동작과 품질 개선 방법을 직접 구현하면서 이해하고, 제한된 Mac의 메모리와 연산 자원으로 어디까지 처리할 수 있는지 확인하려고 시작했다.

최종 활용 예는 회의록에 한정되지 않는다. 고객과의 대화에서 확인한 작업 범위·예산·일정을 견적서 초안으로 만들고, 요구사항을 개발 에이전트에 전달해 PoC를 만드는 것이 목적이다. 이 후속 자동화는 아직 구현되지 않았다.

```mermaid
flowchart LR
    A[음성 수집] --> B[텍스트·화자·시각 추출]
    B --> C[사람이 검토할 수 있는 기록]
    C --> D[외부 AI가 근거와 함께 활용]
    D --> E[견적서·PoC 등 후속 결과물]
```

현재 구현은 녹음·파일 입력, 로컬 전사, 화자·시각 결합, 수정과 버전 관리, 구조화 분석, Markdown·JSON 내보내기까지다. 외부 AI 연결 확대, MCP, 자유 질문, 자동 견적서·PoC 생성은 후속 제안이다.

## 설명을 읽을 때 구분할 세 가지

- **확인한 구현:** 저장소 코드에서 동작을 확인한 내용이다. 기능의 정확도까지 검증했다는 뜻은 아니다.
- **공개된 설명:** 제조사·모델 개발자가 공개한 내용이다. 우리가 실험으로 재현한 결과와 구분한다.
- **제안·미검증:** 개선 방향이나 아직 측정하지 않은 내용이다. 현재 기능처럼 읽지 않는다.

이 문서의 작은 대화·수치 예제는 원리를 설명하기 위해 만든 것이다. 실제 사용자 대화나 성능 측정값이 아니다.

## 먼저 기억할 구분

1. 음성 인식은 생성형 AI 이전에도 통계와 기계학습을 사용했다.
2. 음성의 파형, 전사문, 요약문은 서로 다른 데이터다.
3. 잡음이 줄어든 음성이 항상 전사에 유리한 것은 아니다.
4. 화자 A와 화자 B를 구분하는 것과 실제 이름을 아는 것은 다르다.
5. 프로그램 실행 성공과 실제 대화의 품질 검증은 다르다.
6. 긴 입력을 받을 수 있는 모델도 중요한 조건을 놓칠 수 있다.
7. 원문과 불확실성을 보존해야 이후 AI의 판단을 검토할 수 있다.
