# 한국어 인터뷰 데모

확인일: 2026-10-20. README의 데모 입력으로 FC SEOUL의 공개 한국어 인터뷰를 선택했다. 실제 로컬 모델의 출력과 화면을 기록하며, 모델의 오류를 숨기기 위해 전사를 고치지 않는다.

## 입력과 출처

- 제목: **FC서울 신인 심원성 & 이태석 첫 인터뷰**
- 제작자: **FC SEOUL**
- 공개일: 2021-01-01
- 유튜브 원본: <https://www.youtube.com/watch?v=GnxVJrvGhRE>
- [Commons 파일과 라이선스 기록](https://commons.wikimedia.org/wiki/File:FC서울_신인_심원성_%26_이태석_첫_인터뷰.webm)
- 라이선스: [CC BY 3.0 Unported](https://creativecommons.org/licenses/by/3.0/). Commons에는 2021-11-29 원본 라이선스 검토 기록이 있다. 현재 유튜브 페이지의 라이선스를 직접 확인한 결과와 구분한다.

Commons가 제공하는 원본 WebM을 받았다. 파일 크기는 38,604,519바이트이며 SHA-1은 `dc8c1071616a31aaddee147f2816f84468633a88`로 Commons 기록과 일치한다. FFprobe 기준 영상 길이는 235.001초다. 음성은 48kHz 스테레오 Opus다.

변경 내용은 **영상 전체에서 음성 추출, FLAC으로 변환, 자동 전사·분석, 앱 화면 촬영**이다. 영상의 앞뒤나 중간 구간을 잘라내지 않았다. 추출한 음성은 234,987ms이며, 화면은 초 미만을 버려 `03:54`로 표시한다. 모델용 16kHz 모노 변환은 앱의 기존 FFmpeg 경로에서 수행한다. 인트로 음악을 별도로 제거하거나 질문 자막을 음성 입력에 추가하지 않았다.

원본 영상과 추출 음성은 Git에서 제외한 `data/demo-fcseoul-2026-10-20/`에 보관한다. README에 포함하는 촬영물에는 이 문서와 README의 인접 설명으로 제작자·원본·라이선스·변경 내용을 표시한다. 제작자나 출연자가 이 앱을 보증한다는 뜻이 아니다.

## 환경과 실행 경로

기존에 준비된 Qwen3-ASR 1.7B 8bit, Qwen3-ForcedAligner 0.6B 8bit, Silero VAD, Nemotron 3 Diarization과 Ollama `gpt-oss:20b`를 사용했다. 음성 모델 revision은 [기존 로컬 실행 기록](2026-10-16-local-mvp.md)과 같다. 이번 작업에서 모델을 새로 다운로드하지 않았다.

기존 사용 기록과 분리한 SQLite·파일 저장소에서 실제 FastAPI·워커·웹을 실행했다. 데모 API는 `127.0.0.1:8767`, Vite는 `127.0.0.1:5175`다. 실행 모드는 `local_only`이며 외부 API 키를 전달하지 않았다. 고정 결과를 반환하는 시험 엔진을 사용하지 않았다.

브라우저의 **파일 가져오기**에서 추출한 FLAC을 업로드했다. 별도 저장소를 쓰는 촬영용 실행 파일은 Git에서 제외한 데모 디렉터리에 뒀다. 애플리케이션 코드는 변경하지 않았다.

## 실행 결과와 화면 확인

작업 상태는 `succeeded`, 마지막 단계는 `complete`, `analysis_stale=false`다. 작업 생성부터 완료까지 DB 시각 기준 **259.28초**가 걸렸다. 음성 처리와 분석 이력의 실행 위치는 모두 로컬이며 외부 API 전환은 없다. 모델 준비 상태와 캐시가 있는 한 번의 실행 기록으로, 평균 처리 속도나 긴 녹음의 예상 시간을 나타내지 않는다.

대화 분석은 주제 5개를 만들었다. 질문과 답변·합의·미해결 질문·할 일은 모두 빈 배열이다. 음성에 없는 질문을 영상 자막에서 가져와 채우지 않았다. 분석 개요에도 전사의 `애플 서울` 같은 표현이 남아 있어, 전사 오류가 분석에 전달되는 사례를 확인했다.

연결 가능한 Browser 플러그인 브라우저가 없어 설치된 Playwright Chromium으로 촬영했다. 아래 동작은 실제 데이터와 API를 사용했으며 요청 가로채기나 고정 결과 주입은 없다.

1. 처리 완료된 인터뷰가 기록 목록에 표시되는지 확인했다.
2. 상세 화면에서 27개 발언과 분석 결과를 확인했다.
3. 첫 근거 버튼을 눌러 해당 발언이 선택되고 원본 음성 재생 위치가 **6.168초**로 이동하는지 확인했다.
4. JSON을 내려받아 화면과 같은 전사·분석 버전인지 확인했다. 모든 발언의 `text_edited`는 `null`이다.
5. 목록으로 돌아와 기록이 남아 있는지 확인했다.
6. 위 데스크톱 흐름에서 브라우저 `pageerror`와 실패한 API 응답이 없는지 확인했다.
7. 390×844 화면에서 상세 화면을 열고 가로 넘침이 없는지 확인했다. 아이폰 실기기 검증은 아니다.

브라우저 표시 영역은 1440×900이며 PNG는 페이지 전체 높이로 저장했다. 영상은 **1440×900, VP9, 12.08초의 무음 화면 녹화**다. 모델의 처리 대기 시간과 원본 인터뷰 음성은 녹화 영상에 포함하지 않는다. 화면의 전사·분석을 합성하거나 결과 문장을 수정하지 않았다.

추가 검사에서 실제 내보내기 데이터의 스키마와 근거 참조 검증, 변경 문서의 로컬 파일·목차 링크 62개, Markdown 형식과 `git diff --check`가 통과했다. PNG 3개의 형식·크기와 WebM 전체 디코딩도 확인했다. 애플리케이션 코드를 수정하지 않아 전체 회귀 테스트 묶음은 다시 실행하지 않았다.

## 전사에서 확인한 한계

- 자동 전사는 27개 발언과 익명 화자 2개를 만들었다. 화자 이름과 원문을 수동으로 수정하지 않았다.
- 58.5~60초의 `이태석입니다` 발언에 `unknown_speaker` 표시가 있다. 두 화자를 만들었다는 사실만으로 모든 발언의 화자가 정확하다고 볼 수 없다.
- 27초 부근 영상 자막의 `FC서울`을 해당 전사 구간에서는 `F 세리`로 기록했다. 이후 구간에도 `애플 서블`, `에피소드`, `애프솔` 등 구단명으로 의심되는 오인식이 있다. 고유명사 정확도와 검토 표시가 오류를 충분히 포착하는지 추가 확인이 필요하다.
- 약 68초 경계에서 `왼발에서`가 인접 발언에 중복돼 있다. 긴 전사 창을 결합할 때의 중복 제거도 후속 검토 대상이다.
- 영상에는 화면 자막으로 제시한 질문이 있다. 이 앱은 추출 음성만 받으므로 음성에 없는 화면의 질문을 전사에 복원하지 않는다. 질문이 포함된 실제 음성 대화와 같은 조건으로 해석하지 않는다.

이 입력은 편집된 인터뷰 한 건이다. 정답 전사와 정답 화자 구간을 별도로 작성하지 않았으므로 CER·DER를 산출하거나 품질 합격으로 표시하지 않는다. 전사 오류는 이후 대화 분석에도 영향을 줄 수 있다.

## 다시 실행하기

준비된 환경에서 [Commons 파일 페이지](https://commons.wikimedia.org/wiki/File:FC서울_신인_심원성_%26_이태석_첫_인터뷰.webm)의 원본 파일을 받은 뒤 음성을 추출한다.

```bash
ffmpeg -i fcseoul-original.webm -map 0:a:0 -vn -c:a flac fcseoul-interview.flac
uv run --no-sync meetinglog doctor
bash scripts/dev.sh
```

웹의 **파일 가져오기**에서 `fcseoul-interview.flac`을 선택한다. 모델·캐시·실행 상태에 따라 처리 시간과 결과가 달라질 수 있다. 이번 촬영은 위에서 설명한 별도 데이터 저장소와 포트를 사용했고, 이 명령은 기본 앱에서 같은 입력을 재현하는 절차다.
