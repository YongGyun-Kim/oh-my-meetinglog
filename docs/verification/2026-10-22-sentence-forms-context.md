# 문장 전사·폼별 정리와 실제 컨텍스트 사용량

확인일: 2026-10-22. 개인 녹음 원본과 대화 본문은 이 문서에 포함하지 않는다. 측정 자료는 Git에서 제외한 `data/verification-2026-10-22/`에 둔다.

## 반영한 동작

- 전사는 화자별 턴 안에 문장 목록을 저장한다. 같은 화자의 연속 발언은 무음 간격·검토 표시·ASR 처리 구간만으로 나누지 않는다. 화자 변경·미확인 구간은 경계로 유지한다.
- 문장마다 시작·종료 시각, 원문·수정문, 검토 표시를 보존한다. 클릭은 문장 시작으로 이동하며 종료 시각에서 자동 정지하지 않는다.
- 단어 정렬은 음성 엔진의 중간 자료다. 최종 전사와 JSON 내보내기에는 단어 목록이 없다. 문장 시각을 확인할 수 없으면 기존 구간을 유지하고 `alignment_uncertain`을 표시한다.
- 모델 입력은 화자 정의와 `[문장 참조|화자] "본문"` 형태의 텍스트다. 음성 시각·단어 정보·수정 전 원문·처리 이력은 보내지 않는다. 본문에 나온 기한은 보존한다.
- 정리 결과와 근거 버튼에서 음성 시간을 제거한다. 복수 문장 근거는 유지한다. 구버전 전사·분석은 원래 ID·수정문을 유지해 읽는다.
- 초기 입력 작업은 전사까지만 완료한다. 대화 정리 버튼에서 회의·인터뷰·프로젝트 논의 폼을 선택하고 실행하면 새 분석 작업을 만든다. 폼 선택만으로 호출하지 않으며 다른 폼으로 실행하면 재분석한다.
- RAG·wiki와 후속 에이전트 실행은 추가하지 않았다. JSON 내보내기는 `schema_version: 2`다.

## 실제 샘플과 측정 범위

약 28분 10초의 ALAC/M4A 녹음에서 이미 생성한 전사를 사용했다. 음성 인식 모델은 다시 실행하지 않았다. 기존 476개 전사 구간과 단어별 정렬을 새 저장 구조로 조립한 결과는 412개 턴·586개 문장이다. 조립 전후의 본문을 비교해 공백을 제외한 모든 문자가 유지되는지 확인했다. 문장 경계·화자 구분의 의미적 정확도는 수동 채점하지 않았다.

환경은 Apple Silicon Mac, Ollama `gpt-oss:20b`, 로컬 전용 모드다. 선택한 폼은 `project`(프로젝트 논의), 프롬프트 버전은 `3`이다. 외부 API는 호출하지 않았다.

앱이 요청하는 컨텍스트는 **32,768토큰**이고 최대 생성량은 **4,096토큰**이다. 아래 입력 토큰은 추정 직렬화 크기가 아니라 Ollama 응답의 `prompt_eval_count`다. Ollama가 모델 프롬프트로 계산한 전체 입력의 서버 보고값이며 HTTP JSON 크기나 전사 본문만의 추정 토큰 수와 구분한다. 출력 수는 `eval_count`이며 최종 JSON 본문 길이만을 뜻하지 않는다. [Ollama API의 측정 필드](https://docs.ollama.com/api/chat)

| 요청 | 입력 토큰 | 입력 점유율 | 생성 토큰 | 최대 출력 여유 포함 점유율 | 요청 시간(초) |
| ---- | --------: | ----------: | --------: | -------------------------: | ------------: |
| 1    |     8,136 |      24.83% |     1,619 |                     37.33% |        95.116 |
| 2    |     8,010 |      24.44% |     1,223 |                     36.94% |        82.511 |
| 3    |     8,538 |      26.06% |     1,684 |                     38.56% |       101.415 |
| 4    |     7,714 |      23.54% |     1,966 |                     36.04% |        89.380 |
| 5    |     6,118 |      18.67% |     1,092 |                     31.17% |        92.554 |
| 6    |     5,058 |      15.44% |     1,143 |                     27.94% |        85.466 |

계산식:

- 입력 점유율 = `prompt_eval_count / 32768 × 100`
- 최대 출력 여유 포함 점유율 = `(prompt_eval_count + 4096) / 32768 × 100`

최대 입력은 **8,538토큰·26.06%**, 최대 출력 여유까지 포함하면 **12,634토큰·38.56%**다. 서로 다른 요청의 토큰을 더해서 한 번의 컨텍스트 점유율로 계산하지 않는다. 각 요청은 해당 구간 또는 구간 개요를 별도로 입력한다.

전체 분석은 **546.638초(약 9분 7초)**다. 최초 구간 3개, 구간 처리의 추가 요청 2회, 전체 개요 병합 1회로 총 6회 호출했다. 추가 요청은 기존 형식·근거 검증 재시도 경로에서 발생했으며 이번 측정 로그에는 구체적인 오류 종류를 저장하지 않았다. 모든 요청은 `done_reason: stop`으로 끝났다. 최종 결과는 주제 16개·할 일 11개이며 문장 ID·담당자 ID·기한 원문 검증을 통과했다.

3구간이라는 값은 현재 16,000바이트 분할 설정의 결과다. 모델 컨텍스트를 최대한 채우도록 조정한 결과가 아니다. JSON 스키마와 재시도 안내를 포함한 전체 프롬프트의 한도는 이 바이트 값과 구분해야 한다.

## 해석의 한계

- 한 파일, 한 폼, 한 번의 완주 결과다. 다른 대화 길이·발화량·모델의 점유율과 시간을 보장하지 않는다.
- 2026-10-21 실행과는 입력 구조·문장 단위·폼과 출력량이 달라 단순한 속도 개선율로 비교하지 않는다.
- 근거와 형식 검증은 요약의 의미적 정확성이나 누락 여부를 보장하지 않는다.
- 문장 경계는 전사의 문장부호와 정렬 품질에 의존한다. 시각이 불확실한 구간은 임의 분할하지 않는다. 수동 수정문은 기존 문장의 음성 구간을 가리키며 새로 시간 정렬하지 않는다.

## 검증

`bash scripts/check.sh`를 통과했다. Python 테스트 91개, 웹 컴포넌트 테스트 18개, Playwright 시나리오 3개가 통과했고 Python 정적 검사·포맷, TypeScript 검사, 웹 빌드와 `git diff --check`도 통과했다. Starlette의 기존 AnyIO 별칭 폐기 예정 경고 1개가 남는다.

실제 기록 화면에서 프로젝트 논의 결과 표시, 복수 문장 근거, 문장 시작으로 재생 이동, 폼 선택 취소 시 작업 미생성을 확인했다. JSON 내보내기는 버전 2이며 정리 결과에 음성 시각이 없다. 이전 전사·분석을 지정한 내보내기도 근거를 계속 찾을 수 있다.

측정한 전사·정리 결과는 앱에 새 버전으로 저장했다. 기존 전사·분석·실패 이력은 보존했다. 이 작업은 검증한 결과를 게시한 복구 작업이므로 앱의 해당 작업 소요 시간과 위의 실제 추론 시간은 다르다. 개인 대화 화면 캡처는 공개 문서에 넣지 않았다.

최종 코드를 반영해 웹·API·워커를 재시작한 뒤 API 상태, 폼 3개, 샘플의 완료 상태와 현재·구버전 내보내기를 다시 확인했다.
