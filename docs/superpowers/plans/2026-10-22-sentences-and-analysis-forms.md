# 문장 단위 전사와 폼별 대화 정리 구현 계획

**목표:** 전사는 화자별 턴 안에 문장을 저장하고, 정리용 입력에는 시간 없이 본문·화자·문장 근거만 전달한다. 정리 버튼에서 폼을 고르면 해당 폼으로 새 분석을 실행한다.

**구조:** 음성 엔진의 시간 정렬 결과는 전사 저장 직전에 문장으로 조립한다. 기존 전사·분석은 읽기 호환으로 보존한다. 분석 폼은 작업에 고정해 재시작·재시도에도 유지한다. RAG·wiki와 후속 에이전트 실행은 추가하지 않는다.

**기술:** 기존 Python/Pydantic/FastAPI/SQLite, React/TypeScript. 새 패키지는 추가하지 않는다.

사용자가 구현을 요청했으므로 별도 승인 대기 없이 이 세션에서 직접 실행한다. 기존 미커밋 변경과 사용자 음성 파일을 보존한다. 커밋·push는 하지 않는다.

## 1. 전사와 수정·내보내기

- [x] 먼저 회귀 테스트를 추가해 같은 화자의 연속 구간 병합, 화자 변경·미확인 경계, 문장별 시간, 원문 보존을 확인한다.
- [x] `domain.py`, `recordings/alignment.py`, `transcripts/repository.py`에서 엔진 구간과 저장용 턴·문장을 분리한다. 문장 시각을 확인할 수 없으면 구간을 유지하고 검토 표시를 남긴다.
- [x] `transcripts/service.py`, `transcripts/api.py`, `exports.py`를 문장 ID 기준으로 갱신한다. 기존 전사의 ID와 수정 이력은 유지하고 JSON 내보내기 버전을 올린다.
- [x] 관련 테스트로 잘못된 문장 ID·화자, 중복 ID, 낙관적 잠금과 구버전 읽기를 검증한다.

## 2. 폼별 정리와 작업 전달

- [x] 시간 없는 모델 입력과 복수 문장 근거, 구버전 분석 읽기, 폼별 프롬프트·작업 고정 테스트를 추가한다.
- [x] `analysis/prompts.py`, `chunking.py`, `service.py`, `grounding.py`를 독립적인 정리 입력과 문장 근거로 갱신한다. 주제 시간과 시간 정렬은 제거한다.
- [x] 회의·인터뷰·프로젝트 논의 폼을 제공한다. 선택한 폼은 분석 작업과 결과에 저장하고 워커·자식 프로세스에 전달한다.
- [x] 초기 처리 작업은 전사까지만 완료한다. 별도 정리 요청만 분석을 실행한다. 취소·복구·진행 시간 제한은 유지한다.

## 3. 화면·실제 샘플 검증

- [x] 전사 화면은 화자별 턴 안에 문장을 표시하고 문장 시작으로 이동·수정한다. 정리 화면에서는 시각 없이 근거를 표시한다.
- [x] 대화 정리 버튼에서 폼 선택 창을 열고, 실행 버튼을 누를 때만 해당 폼의 작업을 등록한다. API 계약·브라우저 테스트도 갱신한다.
- [x] `bash scripts/check.sh`를 통과시킨다.
- [x] 사용자 샘플의 저장된 전사로 실제 로컬 분석을 실행해 각 요청의 `prompt_eval_count`, 출력 토큰, 설정된 32,768 컨텍스트 점유율을 기록한다. 호출별 컨텍스트를 합산하지 않는다.
- [x] README와 검증 기록에 현재 구조·실행 흐름·측정 범위와 한계를 기록한다. 개인 대화 본문과 원본은 공개 문서·Git에 넣지 않는다.
